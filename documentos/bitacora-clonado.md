# Bitácora de repositorios clonados

## 1. Repositorio del compañero

### ¿Cuántos commits tiene y cuál fue el primero?

El repositorio del compañero tiene 24 commits. El primer commit corresponde a la creación inicial del repositorio.

### ¿Su estructura de carpetas se entiende sin preguntarle nada? ¿Qué le cambiaría?

La estructura de carpetas se entiende fácilmente porque está organizada en categorías claras: `Cuadernos/`, `Documentos/`, `Proyectos/` y `Talleres/`. Además, el README explica qué contiene cada una de estas carpetas, por lo que no sería necesario preguntarle al autor para saber dónde buscar el material.

Lo que cambiaría sería mantener un mismo estilo de nombres en todo el repositorio. Por ejemplo, usaría nombres en minúscula (`cuadernos/`, `documentos/`, `proyectos/` y `talleres/`) para mantener una estructura uniforme. También organizaría los cuadernos en orden numérico y, dentro de `Proyectos/`, utilizaría subcarpetas específicas para cada proyecto.

### ¿Su README me permitiría usar su proyecto sin ayuda?

Sí, el README permite entender la organización general del proyecto y saber dónde encontrar los cuadernos, talleres, proyectos y documentos. También explica brevemente los aprendizajes del curso.

Sin embargo, para utilizar el proyecto completamente sin ayuda, sería conveniente agregar instrucciones más detalladas sobre cómo ejecutar los cuadernos y proyectos, qué programas o librerías se necesitan y cómo reproducir los resultados. Por eso, considero que el README es suficiente para orientarse en el repositorio, pero podría mejorar en las instrucciones prácticas de uso.

## 2. Comparación de los tres repositorios

Los tres repositorios tienen objetivos diferentes y, por eso, están organizados de distintas maneras. `git-novice` está estructurado como material educativo, con una organización orientada a seguir una lección. `seaborn-data` tiene una estructura más sencilla porque su objetivo principal es almacenar datasets para su uso en ejemplos y análisis. El repositorio de mi compañero está organizado por categorías del curso: `Cuadernos/`, `Documentos/`, `Proyectos/` y `Talleres/`.

Considero que el repositorio de mi compañero tiene una organización especialmente clara para un proyecto académico, porque separa el material según su función y su README explica qué contiene cada carpeta. Sin embargo, `git-novice` también presenta una estructura adecuada para su propósito educativo y `seaborn-data` mantiene una organización simple acorde con su función de repositorio de datos.

En general, lo más importante que aprendí de la comparación es que una buena organización depende del propósito del repositorio: las carpetas, los nombres de los archivos y el README deben permitir encontrar rápidamente lo que se busca.
